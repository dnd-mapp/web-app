# Design system

## Tokens

The design system lives under [projects/web-app/src/design-system](../projects/web-app/src/design-system) and, for now, consists of design tokens: named CSS custom properties that hold every color, typography and spacing value the application uses. They come in three layers. The primitive and semantic layers are declared on `:root`, one SCSS partial each under `tokens/`, and the folder's `_index.scss` loads both; [styles.scss](../projects/web-app/src/styles.scss) loads that index once with `@use`, so the custom properties exist on every page and a component stylesheet reads them with `var()` without importing anything. The component layer is spread across the repository: each component declares its own tokens in its own stylesheet.

### Primitive tokens

[\_primitive.scss](../projects/web-app/src/design-system/tokens/_primitive.scss) holds the raw values, named after what they are rather than where they are used: `--color-gray-500`, `--font-family-sans`, `--font-size-100`. Each color is a complete eleven step scale written in `oklch()`, numbered `50`, `100`, `200` through `900`, `950` from light to dark, with the lightness falling in even steps. There are two: a near neutral gray whose chroma deepens slightly toward the dark end, and a blue that carries the accent, whose chroma peaks around the middle of the scale and falls off toward either end, since a color reads as itself the strongest there. Both scales share their lightness steps, so a semantic token swaps one for the other without the value around it changing weight. The font size scale has eight steps in `rem`, numbered `50`, `75`, `100`, `200` through `600`, with `100` as the body size: the two steps below it serve captions and compact controls, the steps above it serve headings. Line height is a unitless ratio and uses the same numbering, with `100` as the body value. The spacing scale has eight steps in `rem` on a 4px grid, numbered `50`, `100`, `200` through `700`, and serves padding, gaps and the dimensions of controls alike; there is no separate size scale. The radius scale has three steps in `rem`, numbered `100` through `300`, for the corners of controls and panels. A style declaration never references a primitive directly: only a semantic token or a component token does.

### Semantic tokens

[\_semantic.scss](../projects/web-app/src/design-system/tokens/_semantic.scss) names each value after its purpose in the interface and maps it onto a primitive: `--color-text` and `--color-background` for the page, `--color-surface` and `--color-border` for a bar or panel that sits on it, `--color-control`, `--color-control-hover` and `--color-control-active` for an interactive control at rest, under the pointer and pressed, the same three under `--color-control-primary` for the control that carries the one action a page leads with, `--color-text-on-control-primary` for the text that sits on it, which is dark because the accent is a light fill, `--color-focus-ring` for the outline keyboard focus draws, `--text-body-family`, `--text-body-size` and `--text-body-line-height` for body text, and `--text-control-size` for the text of a compact control. These are the tokens that global styles and component tokens reference. The file also sets `color-scheme: dark`, since the mapping it holds is the dark theme; a second theme would remap the same semantic names onto other primitives.

### Component tokens

A component declares the values its styles use as tokens of its own, on `:host` at the top of its stylesheet, named after the component and the property: `--top-bar-height`, `--top-bar-background-color`. Its style rules reference those tokens and nothing else, so every value a component uses is listed in one place, next to the styles that use it, and reads as a decision rather than a number. A component token maps onto a semantic token wherever one names the purpose, as the colors do. A measure that has no purpose across the interface, such as a component's height or padding, maps onto the spacing scale directly, since a semantic layer for every dimension would restate the component's decisions under another name. A variant of a component declares its values in the same list, then a rule below the `:host` block points the tokens the variant changes at them, as `:host(.primary)` in the button does, so the style rules are still written once and every value the component can take reads from one place. [top-bar.component.scss](../projects/web-app/src/shared/components/top-bar/top-bar.component.scss) and [button.component.scss](../projects/web-app/src/shared/components/button/button.component.scss) are the pattern to copy.

### Adding a token

A scale enters the primitive layer whole: all eleven steps of a color, all eight of a font size. Its steps only make sense relative to each other, and a semantic token then picks from a fixed set rather than introducing a value of its own. Every other token is added when a style needs the value, not ahead of it: line heights, font families, the semantic tokens and the component tokens describe what the application uses today, so an unused one is removed rather than kept for later. To add one, put the raw value in the primitive layer under a name that describes the value, add a semantic token that names the purpose and points at the primitive when the value has one, and reference it from a component token that the style reads. When a value already exists as a primitive, only the tokens above it are new. [Stylelint](linting.md#styles) checks the partials along with the rest of the SCSS.
